# Mine2YourLingo workspace console

Responsive React + TypeScript admin portal backed by the real NestJS API. It uses the official brand asset and the light navy, blue, teal, and amber visual language of the supplied mobile reference.

## Run locally

Use Node.js 22 or newer. From `apps/admin-web`:

```sh
npm ci
cp .env.example .env
npm run dev
```

Open `http://localhost:5173`. The API must be running at `http://127.0.0.1:3100` with development authentication explicitly enabled; Vite proxies `/v1` to that local API by default. Set `DEV_API_URL` if your API uses another port. Deployment containers use port 3000 internally. Sign in with a display name and language. Administrative aggregate access requires the development admin key configured on the API server; entering a display name alone never grants administration.

`VITE_API_URL` defaults to the same-origin `/v1` path and is read at build time. A deployment reverse proxy must route this path to the API. `DEV_API_URL` controls the development-only Vite proxy target. Production API connections require HTTPS; insecure HTTP is accepted only for loopback development. Deploy the `dist/` directory generated by `npm run build` on a static host. Never put provider credentials or the development admin key in a `VITE_` environment variable: these variables are public.

## Implemented behavior

- Explicit local authentication, tab-scoped sessions, token refresh, and server session revocation on logout.
- Server-reported aggregate metrics for authorized administrators; account-scoped metrics for members.
- Create, rename, delete, join, and leave private groups; generate expiring invitation tokens.
- Member language visibility, role changes, and confirmed removals with server authorization.
- Actual monthly usage, API-enforced quotas, and estimated cost ledger values.
- Cost planning with explicit current provider rates, unit conversions, and revenue share. No provider rate is assumed to be free; missing rates block estimates for used stages.
- Provider configuration and known limitations from the API. Credential presence is described as configured, not proof of availability or translation quality.
- Configured plan catalog, disabled purchases, and no client-created paid entitlements.
- Profile and language preferences, personal JSON export, and typed confirmation for account deletion.
- Responsive sidebar, mobile navigation, keyboard focus states, reduced-motion support, loading states, and actionable API errors.

## Verification

```sh
npm run typecheck
npm test
npm run build
npm audit --omit=dev
```

Automated tests cover authenticated API requests, authorization and network failures, HTTPS configuration boundaries, empty delete responses, missing pricing, invalid costs, and usage unit conversion. A manual API integration pass must cover login, group creation and invitation joining using a second user, unauthorized member mutations, refreshed usage, export, and deletion. Run mobile and desktop viewport checks against the local server.

See `VERIFICATION.md` for the completed live API integration checks and the remaining browser and production validation. Typography is bundled locally with font license notices in `public/`.

## Boundaries and pending features

The simulator is not production authentication. Phone/email sign-in, commercial purchase flows, support cases, abuse-report triage, feature flag editing, production system configuration changes, and financial reconciliation are not implemented in this console. These require verified backend contracts and external integrations. It does not expose private transcript/audio browsing or claim end-to-end encryption. The cost calculator is a planning tool, not provider billing reconciliation; storage, infrastructure, bandwidth, taxes, and currency conversion are excluded. LLM token quantities are entered manually because the account usage endpoint does not return them.

Sessions are kept in `sessionStorage` so they do not survive closing the browser tab. Production hardening should use a reviewed cookie/session design, a restrictive content security policy, and a dedicated production sign-in flow. No production deployment is claimed by this implementation.
