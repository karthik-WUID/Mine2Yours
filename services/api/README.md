# Mine2YourLingo API

NestJS modular monolith for identity, private groups, multilingual messages, realtime, usage and privacy. This implementation is runnable locally and has verified security/cost tests; it is not a commercial launch certification.

## Local development

Use Node 22 or newer and npm 10 or newer (packageManager pins npm 11). Host npm 8 does not apply security overrides correctly. This machine's usable runtime is `/Users/utvyakta.com/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node`; its system Node 14 is unsuitable. Run from this directory:

```sh
npm ci
npm run prisma:generate
cp .env.example .env
# Adjust local secrets yourself; keep .env outside version control.
PORT=3100 npm run dev
```

The normal API port is 3000. Port 3100 is used on this machine because another user's application owns 3000. `npm run dev` watches TypeScript, compiles successfully, then restarts the compiled Nest process; Nest dependency metadata must be emitted by TypeScript. `npm run build && npm start` runs compiled source. `npm test` builds and runs the default suite of 23 tests. For an isolated empty PostgreSQL database, `TEST_DATABASE_URL=… npm run test:postgres` applies the migration and tests actual normalized persistence; never use a real-user database.

With DATABASE_URL unset, development uses `.local/api/state.enc`, AES-256-GCM protected by `.local/api/development.key`, both filesystem mode 0600 under a mode 0700 directory. This explicitly isolated single-process store is never permitted in production. Back up/remove the entire local directory together; changing the key makes existing data unreadable. The local key lives next to data and is not equivalent to managed production KMS protection. Development auth requires `ENABLE_DEV_AUTH=true`; it creates an identity and never verifies a phone. Aggregate admin privileges additionally require a matching explicit DEV_ADMIN_KEY. There are no seeded people or fabricated translations. npm 11 install-script policy is pinned for required Prisma/compiler/native optional dependencies and denies Scarf telemetry.

Use PostgreSQL by setting DATABASE_URL, then `npm run prisma:generate && npm run db:migrate`. The checked-in migration contains normalized relational users, sessions, memberships, invitations, messages, recipient receipts, per-language translations, usage events, subscriptions, devices, audit events and billing event uniqueness. Private row payloads are application encrypted; relation IDs remain indexed metadata. Only the owning user and authorized communication participants are returned by APIs. Admin access is aggregates only.

## Genuine provider integrations

- Verified OTP: Twilio Verify with account SID, auth token and Verify service SID. OTP codes are checked by Twilio; only an approved verification for the same E.164 phone produces a session. Local auth is forcibly rejected in production. SMS requests are bounded per phone and by a persisted daily service cap, in addition to HTTP limits.
- Translation: Google Cloud Translation Basic v2 with GOOGLE_TRANSLATE_API_KEY. Google lists Tamil, Bengali, Hindi and Odia in its language support documentation. This is configuration support, not evidence of quality for the pilot. The adapter explicitly selects standard NMT (`model:nmt`) and never routes ordinary instructions to a premium LLM. Alternatively, TRANSLATION_HTTP_URL accepts a LibreTranslate-compatible POST `/translate`; self-hosted model support must be checked per language.
- STT: explicit OpenAI transcription model or STT_HTTP_URL contract documented in `.env.example`. No default paid model is enabled. Client configured source language is passed through; no invented confidence score is returned.
- TTS: explicit OpenAI speech model or TTS_HTTP_URL. When unconfigured, messages contain translated text without claiming cloud audio exists. Mobile must verify an installed local voice before playback. AI speech must be identified to users as synthesized.
- Audio objects: S3-compatible storage using the AWS standard credential chain, with application AES-GCM protection before upload. Production additionally uses SSE-S3 by default. MinIO development without KMS can explicitly choose S3_SERVER_SIDE_ENCRYPTION=none while retaining application encryption. Provision the bucket separately. Authenticated URLs are user-bound and valid five minutes; current membership is checked at fetch.
- Reliability: Redis-backed BullMQ durable text-processing jobs and Redis Pub/Sub events when REDIS_URL is configured. Queues contain only message IDs, not transcripts or recordings. Local development uses bounded asynchronous in-process execution. A crashed raw-audio transcription cannot be retried from retained audio because raw uploads are not retained; user must upload again.

Provider traffic requires an explicit positive unit rate, AI_PRICING_VERSION, AI_PRICING_CONFIRMED=true, and the sender's recorded providerConsent. Example rates are conservative development estimates and must be replaced with contractual provider pricing. Missing configuration fails with an explicit error and does not fabricate recognition, translation, speech, or billed-provider success. Provider outputs are bounded, timeouts enforced, redirects rejected, production endpoints use HTTPS, and repeated failures open circuit breakers.

Official integration references: [Twilio Verify](https://www.twilio.com/docs/verify/api/verification-check), [OpenAI transcription](https://developers.openai.com/api/docs/guides/speech-to-text), [OpenAI speech](https://developers.openai.com/api/docs/guides/text-to-speech), [Google translation](https://docs.cloud.google.com/translate/docs/translate-text), [Google language support](https://docs.cloud.google.com/translate/docs/languages), [LibreTranslate](https://docs.libretranslate.com/api/operations/translate/).

## Cost and delivery behavior

Processing reserves a conservative upper-bound budget atomically before provider calls. Per-user message/voice quotas, daily/monthly user budgets, group monthly budgets, and global service daily/monthly budgets are checked against persisted usage including outstanding reservations. Global caps and active plan limits must be finite and nonnegative. Empty, malformed, infinite or negative global caps prevent reservations with sanitized `503 USAGE_LIMITS_INVALID`; zero is a valid cap that pauses paid work with `429 GLOBAL_BUDGET_EXCEEDED`. Each async provider stage rechecks configuration so a malformed limit stops subsequent calls. Language fanout reuses one translation/audio per unique listening language. Cache keys include ownership/conversation scope, text, source/target, glossary/model and voice version; no global sensitive-message cache exists. Cache retention never exceeds message retention. Group/account deletion preserves a pseudonymized financial usage ledger so deletion cannot reset the service spending cap. Failed attempts are conservatively estimated as attempted work; invoice reconciliation is not implemented. Estimated costs are never labeled measured invoice costs.

PCM WAV metadata supplies authoritative duration (0.1–60 seconds); a client duration cannot evade voice quotas. Silent recordings are rejected before recognition. Raw recording buffers are discarded after STT. Source audio, detected numerals/safety phrases and explicit review requests require sender review before release. Changed digit quantities block confirm. Indic numeral normalization covers initial language digit sets. These checks cannot prove translated meaning or preservation of spelled quantities/negation/units; pilot speaker evaluation remains required. Consent, sender membership and remaining recipient authorization are checked again before each external stage.

Messages progress PROCESSING→READY or REVIEW_REQUIRED/FAILED/CANCELLED. The sender must explicitly confirm a review. Receipts remain PENDING until a device acknowledges fetch; DELIVERED→PLAYBACK_STARTED→PLAYBACK_COMPLETED are ordered recipient reports. No state asserts that a human understood the instruction. Message and audio reads enforce current membership and direct-conversation participants. Realtime emits IDs and state only; reconnect must fetch history. Removed members and revoked sessions lose realtime/audio access.

Plans are indicative business hypotheses in source, optionally replaced by a reviewed PLANS_JSON array. Paid entitlements are unlocked only by a configured trusted HTTPS receipt-verification gateway that verifies platform/store ownership, provider, product and subscription state. The default configuration rejects purchases. Billing webhooks require timestamped HMAC over exact raw bytes, deduplicate provider events, and bind a previously verified billing customer. This abstraction is not an implemented Apple/Google store verifier. Provider-specific server verification, refund reconciliation, ordering and grace periods remain release work. Admin revenue is unavailable rather than synthesized zero.

## Deployment and release gates

Production startup requires PostgreSQL, Redis, managed encryption/signing keys, explicit global budgets and a pricing version; development authentication cannot be enabled. Put the API behind TLS, configure TRUST_PROXY narrowly for the real load balancer, configure explicit browser origins, and use IAM roles/secrets management. Production WebSocket ingress must enforce TLS and trusted proxy headers. Security metadata logs contain only request ID, method, route template, status and latency; transcripts, audio, tokens, phone numbers and provider URLs are omitted. Error responses do not echo malformed request bodies.

The following remain **unverified or incomplete**:

1. The initial migration and actual Prisma/PostgreSQL 16.14 runtime passed an isolated portable database test: encrypted normalized persistence, two Prisma clients, concurrent idempotency, advisory transactions, private access, receipts, token rotation and deletion/ledger retention. Production deployment migrations/backup restoration still require your infrastructure checks. Redis jobs/pubsub and S3 interactions remain unverified because this host has no Docker/Redis/S3 deployment. The temporary database/binaries were removed after testing.
2. The initial production store loads normalized rows into memory and serializes mutations with an advisory transaction lock. Replace this with scoped, paginated Prisma repositories and separate transactional budget ledgers before a scale launch. In-memory HTTP/circuit limits are per-instance; Redis-backed distributed rate/circuit policies remain required for horizontal scale.
3. Actual Tamil→Bengali, Bengali→Tamil, Hindi/Odia STT/translation/TTS, latency and quality are not verified without configured credentials and speakers. No real cloud call was made by automated tests. Tests use explicitly labeled fixtures and local HTTP contract servers.
4. Native background playback, locked/force-stopped devices, Bluetooth, FCM, store policies and batteries require physical-device testing. A backend WebSocket cannot guarantee delivery into OS suspended applications.
5. Provider invoice reconciliation, versioned cost tables, full OTel tracing/monitoring exporters, terminology normalization/fallback LLM routing, organizations, abuse/blocking, join approvals, full financial refunds/grace flows and platform-specific billing verification remain incomplete.
6. Retention/deletion runs at startup/hourly and removes tracked derived objects. Configure S3 lifecycle limits plus an orphan-object sweeper, backup expiry/deletion, legal financial retention and key rotation/recovery before release. Logs contain no message content; transport and application encryption do not constitute end-to-end encryption.
7. Paid plan defaults have no commercial validation. Production privacy/legal assessments, dependency vulnerability review, key management, backup restore and deployment audits are release gates, not compliance claims.

Provide a reviewed exchange-rate assumption; no current exchange rate is implied. It explicitly excludes fixed infrastructure/storage/bandwidth/payment fees and labels unreviewed prices.
